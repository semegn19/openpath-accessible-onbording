## 1. Product Direction & Value Proposition

> **“Tell Roha what is stopping you. It helps you register and apply for work—even when you cannot understand a question, provide standard ID, or stay connected—while keeping support needs private.”**

Roha is an accessible, conversational drop-in component designed for Ethiopian learners and job-seekers. It transforms standard websites and onboarding portals into guided, multi-modal conversational journeys supporting voice, keyboard, touch, and screen-readers.

### Three Signature Experiences
1. **“I’m stuck”:** Understands the learner's difficulty and offers an approved, permitted next step:
   - *“I don’t understand”* → Simplifies wording and offers plain read-aloud.
   - *“I can’t read this”* → Enlarges typography to 150%/200% and speaks the question.
   - *“I don’t have that document”* → Explains alternative ID routes (Refugee ID, Kebele letter, or no-document partner referral).
   - *“I can’t type”* → Activates voice input or offers partner-assisted onboarding.
   - *“Someone is helping me”* → Activates assisted mode with recorded learner consent and final review.
   - *“My connection stopped”* → Reassures learner that drafts are safely preserved locally on-device.
   - *“I don’t want to answer”* → Explains optional fields and guides to "Prefer not to say".
2. **“Check my answer”:** Reads back recorded answers in full and supports precise conversational corrections:
   - Full read-back: *“Read all my answers”* / *“Check my answers”*.
   - Patronymic preservation: *“Keep my first name; change my last name to [name]”*.
   - Immediate undo: *“Undo that change”* (reverts to previous recorded value).
   - Spoken digit normalization: Converts spoken number words (*“zero nine one one...”*) to numeric strings (`0911...`).
3. **“Continue where I stopped”:** Preserves progress across reloads, accidental tab closures, and connection failures:
   - Automatic local draft persistence.
   - Orientation recap on return (*“Welcome back, we are on step 3 of 8: Phone number”*).
   - Clear shared-device explanation and instant draft erase control.

## 2. Respecting the Host Website & Component Packaging

### Embeddable Component
- Packaged as a single lightweight bundle (`dist/roha.js`, ~70 KB raw / ~22 KB gzipped).
- Declarative Custom Elements: `<roha-agent>` and `<roha-assistant>`.
- Configurable attributes:
  ```html
  <roha-agent language="am" theme="default" form-mode="guided" api-endpoint="/api/submissions"></roha-agent>
  <script defer src="/roha.js"></script>
  ```
- **Scoped styling:** Assistant UI uses prefixed CSS classes (`.roha-*`) and inline SVG icons, avoiding host stylesheet contamination.
- **Dual-Host Support:**
  1. **Savanna Platform:** Runs inside Savanna (`/onboard`, `/job`, `/employer`).
  2. **Independent Blank Host:** Demonstrates complete functionality on an unstyled, framework-free HTML page (`demo/blank-host.html`).

## 3. Architecture & Trust Boundaries

```mermaid
flowchart TD
    User["Learner (Voice / Keyboard / Touch)"] --> Component["<roha-agent> Component"]
    Component --> Engine["Form & Conversation Engine\n(One question/screen, Back/Next, Progress)"]
    Component --> Discovery["Semantic Discovery & Target Registry\n(Discovers inputs, names, options; NO PII exported)"]
    Component --> Router{"Dual-Layer Intent Router"}
    
    Router -->|Layer 1: Local Rules (<1ms)| Validator["Intent & Schema Validator"]
    Router -->|Layer 2: Unmatched Phrases| LLM["Pluggable Model Provider Hub\n(Local Ollama llama3.2:1b / Chrome Nano / Custom)"]
    LLM -->|Structured RohaIntent JSON| Validator
    
    Validator -->|Valid Target & Schema| Executor["Execution Engine\n(TextScale, SimpleMode, Contrast, FormAction)"]
    Validator -->|Malformed / Forged| Reject["Safe Rejection with Audio Announcement"]
    
    Executor --> Outbox["Idempotent Outbox Queue\n(IndexedDB / LocalStorage)"]
    Outbox -->|Online / Sync| Backend["OpenPath Backend / Host API\n(POST /api/submissions)"]
```

### Trust Boundary Isolation
- **The LLM has zero DOM or shell access:** The model never executes JavaScript, selects raw CSS selectors, or accesses the filesystem. It can only propose structured JSON intents adhering to `intent.schema.json`.
- **Target Registry Protection:** Any proposed `targetId` must exist in the active `DiscoveredPageMap` generated by the runtime discovery engine. Invented target IDs or stale map references are rejected.
- **Strict Private Support Separation:** Learner support preferences (disability, screen reader, simple language, "Prefer not to say") are stored separately and **never transmitted to employers or in public job application payloads**.
- **Idempotent Submissions:** Submissions use UUID-based `clientRef` tokens to prevent duplicate applications during dropped network reconnects.

## 4. Model Selection & LLM Architecture

- **Primary Local Model:** Self-hosted Ollama running `llama3.2:1b` or `qwen3:1.7b` at `http://localhost:11434`. Zero cost, zero external API keys.
- **Provider Interface:** `LLMProvider` interface allows 1-line switching across:
  - `OllamaLLMProvider` (Local offline/LAN)
  - `OpenAILLMProvider` (OpenAI, Groq, DeepSeek, vLLM)
  - `GeminiLLMProvider` (Google Gemini 1.5 Flash/Pro)
  - `AnthropicLLMProvider` (Claude 3.5 Sonnet/Haiku)
  - `ChromeBuiltInAIProvider` (On-device Gemini Nano via `window.ai`)
  - `GenericRESTProvider` (Custom enterprise webhooks)
- **Minimal Context Sending:** Only sends the current question label, allowed intent names, approved plain explanations, and immediate utterance. Never sends page HTML, session tokens, or unrelated answers.

## 5. Offline, Speech, and Language Honesty

1. **Offline Capability:**
   - Guided form interaction, progress preservation, draft recovery, text scaling, contrast switching, and simple mode operate **100% offline**.
   - Offline banner clearly indicates: *"Saved on this device — answers will sync automatically when connected"*.
2. **Speech Recognition (`ASR`):**
   - Web Speech API (`webkitSpeechRecognition`) uses native Chrome engine (`am-ET` and `en-US`).
   - Requires explicit user gesture (button click) for microphone permission. Always offers typing as a full alternative.
3. **Read-Aloud (`TTS`):**
   - Chrome English TTS is fully native.
   - Amharic uses bundled high-fidelity phoneme audio prompts for every onboarding step when local synthetic voices are unavailable.
4. **Localization Architecture:**
   - Complete dictionary and UI mapping for English (`en`) and Amharic (`am`).
   - Structural language packs ready for Tigrinya (`ti`) and Afaan Oromo (`om`). Capabilities marked honestly in the capability matrix.

ARCHITECTURE REQUIREMENTS

Keep the SDK light and provider-independent. Use the current framework if suitable. The core must not require a large model download or paid API. Local command rules handle essential preferences/navigation; an optional local LLM proposes structured intents for flexible wording. Your deterministic validator checks schema, current map version, target, allowed arguments, host authority, consent and confirmation before executing. The model never supplies executable code or grants itself permissions.

Use schemas/ for contracts and examples/ for illustrative shapes. The actual runtime must generate the website map from the DOM; illustrative JSON examples are not proof of discovery. Keep DOM handles in a local registry and omit raw HTML, selectors, field values, credentials and hidden/private content from exported maps. Debounce relevant route/DOM updates and protect against stale targets.

Support device-local, local-network hub and optional remote profiles explicitly. Keep processing local by default; no silent cloud fallback or telemetry. Host authentication, CSRF, upload checks and current-session permission must still apply. Never scan desktop folders, bypass native file-dialog permissions, infer disability/status, or leak private support into public/employer payloads.

# Roha three-minute demonstration

Rehearse the actual tested build. Do not claim unsupported language, wake, offline, partner or submission capability. Use synthetic applicant records and clearly labelled sample jobs. Use actual co-designer findings with their permission, not invented testimonials.

| Time | Show | Evidence / point |
| --- | --- | --- |
| 0:00-0:25 | The same Roha script on a second ordinary host with no custom basic-form map | Adoption and automatic discovery |
| 0:25-0:50 | Enable the verified speech profile, activate Roha if tested, enlarge real text, then reset | Actual interaction rather than a decorative microphone |
| 0:50-1:25 | Ask for a simple explanation, answer a form question, correct a deliberately misheard value | User control, clear language and usable voice |
| 1:25-1:50 | Choose an allowed no-national-ID route and a private support need; show review/public payload separation | Inclusion and privacy |
| 1:50-2:15 | Filter sample jobs by declared accommodation and open the shared application flow | Required career gateway |
| 2:15-2:40 | Demonstrate the tested offline reload/recovery profile; state if LAN is required | Ethiopia and low-connectivity suitability |
| 2:40-3:00 | Show actual co-designer/task evidence, installation time, axe/human checks and truthful cost/limits | Quality, sustainability and credibility |

Prepare a text/keyboard backup because it is part of accessibility. If real speech fails, state the failure and show the fallback; do not present a mock as working ASR. If complete co-designer/device testing is unavailable, explicitly mark it pending rather than showing a pass badge.

Suggested evidence board: actual task completion/assistance; actual test device/language; measured install time; real bundle size; actual automated findings; offline request trace; privacy export checks; model licences and known gaps.
